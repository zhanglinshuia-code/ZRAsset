# 资源分发与服务接入

[文档首页](../index.md) · [启动](startup.md) · 下一篇：[平台集成](platforms.md)

本包提供客户端资源更新能力。资源文件可以部署到 HTTPS 文件服务器或 CDN；签名版本描述由项目自己的发布服务提供。

## 上传构建内容

1. 使用编辑器构建目标平台的资源包。
2. 将清单以及其引用的 Bundle、RawFile、Archive 文件部署到同一个资源版本目录，保留文件名与相对路径。
3. 设置客户端的资源内容根地址，确认可以访问清单和所有引用文件。
4. 需要随安装包提供的内容，使用编辑器的“拷贝当前构建到首包目录”。

已发布版本应保持不可变。修改内容时创建新资源版本，避免文件哈希、缓存和版本描述不一致。只上传部分 Bundle 不能构成完整的可用版本。

## 配置签名版本

`SignedReleaseUrl` 指向签名版本描述，`RemoteBundleBaseUrl` 指向资源内容根，两者不能互换。客户端预置受信任的公钥及 Key ID；私钥仅由发布方保管。

运行时通过 `FetchSignedReleaseAsync` 检查签名、版本身份、有效期与序号，随后准备缺失内容并激活版本。完整调用顺序见[下载与版本更新](updates.md)，启动配置见[启动和 HybridCLR](startup.md)。

内容上传完成后，再更新对外发布的版本描述。业务请求中的访问凭据通过网络策略注入，避免写入配置资产或资源包。

## 多包与回滚

多个包需要一致切换时，使用 `ResourceReleaseSetManager` 准备全部成员并激活集合。回滚前关闭旧消费者并确认目标版本文件可用；签名发布序号应继续递增，不能降低防回退要求。

生产接入时检查包名、平台、版本、宿主 ID、公钥和内容根的一致性。网络错误、版本不可用或内容校验失败应交由业务界面提供明确的重试与恢复入口。
