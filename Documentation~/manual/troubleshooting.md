# 诊断与常见问题

[文档首页](../index.md) · [平台集成](platforms.md)

## 按阶段定位

先判断错误发生在构建、初始化、检查发布、准备、激活、Unity 加载还是释放阶段。保留完整异常及内部异常，不只截取最后一行 Message。ResourceFailure 提供错误码、阶段和恢复建议；主错误与清理错误同时发生时，会保留在聚合异常中。

| 现象 | 原因方向 | 建议操作 |
| --- | --- | --- |
| 找不到地址 | 地址大小写、规则前缀、清单未更新 | 比较运行中的清单地址和构建配置 |
| 清单身份不匹配 | 包名、版本或平台不一致 | 检查实际打开的 manifest，确认根路径 |
| Bundle 加载失败 | 平台、文件损坏、加密或依赖错误 | 从文件长度/哈希开始，随后检查 Unity 和解密错误 |
| 更新下载量与界面不同 | 把逻辑 Diff 当成实际缺失量 | 使用准备计划，区分缓存命中和网络需求 |
| 关闭或激活被拒绝 | 仍有 Handle、Scope、流、实例或场景 | 查看所有权诊断，关闭业务使用者 |
| await 一直未完成 | 调度未推进、Unity 请求或用户确认未结束 | 查看操作树、当前阶段和是否等待确认 |
| 同步读取失败 | 文件来源不支持同步，或内容尚未准备 | 改用异步入口，避免主线程阻塞 |
| 升级后鉴权配置不同 | 同时提供两处 NetworkPolicy | 按 0.35 优先级显式选定一个策略 |

## 资源没有卸载

先查看是否还有有效所有权，再检查延迟卸载和回收调用。Material 引用 Texture、场景对象引用 Prefab 组件资源，都可能延长 Unity 内部引用寿命；框架引用数归零也不保证系统内存立即下降。不要只通过任务管理器的进程内存判断泄漏。

用重复进入/退出同一业务的测试观察资源统计、Scope 条目、加载 Bundle 数和 Unity Profiler 趋势。创建栈诊断可按需开启，不宜把高成本堆栈采集默认放到所有生产加载。

## 取消后还有请求

取消只终止本消费者的等待；共享消费者、Unity 原生不可取消操作和必要清理仍可能继续。应用应该等待关闭屏障，不应在取消按钮点击后马上删除缓存目录。

## 首包与缓存不一致

核对运行时实际 Root、包名和清单格式。首包存在不表示首包版本已激活；活动指针指向缓存版本时，运行时应遵循该版本的内容身份。不要把未校验文件覆盖进既有版本目录以“修复”问题，应重新构建新版本或使用框架的恢复流程。

## 开发模式与关闭 Domain Reload

Editor Play Mode 退出需要清理异步操作和包注册。快速再次进入播放时，上一会话可能还在排空；应等待或处理明确错误，而不是手动清空全局字典跳过资源释放。自定义后端不能在原生请求仍使用文件时报告已关闭。

## 报告问题时提供什么

提供框架版本、Unity 版本、目标平台、最小复现、资源版本/清单格式、完整错误及相关日志。记录实际运行的包路径，确认使用的是预期的包版本。需要给出缓存结构时去掉令牌和生产密钥内容。
